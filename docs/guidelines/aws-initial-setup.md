# AWS アカウント初期設定ガイド

新規 AWS アカウント作成後に実施すべきセキュリティ・コスト管理・監査設定をまとめる。
本プロジェクトのルール（`ap-northeast-1` 固定・月額 ¥1,500 アラート等）は [aws-rules.md](aws-rules.md) に従う。

---

## 優先度 A：即時対応（アカウント作成直後）

### 1. ルートユーザーの MFA 有効化

**目的**: フルアクセス権限を持つルートユーザーの不正利用を防止する。

**手順**:

1. ルートユーザーでマネジメントコンソールにサインイン
2. 右上のアカウント名 → **セキュリティ認証情報** を選択
3. **MFA デバイスの割り当て** をクリック
4. デバイス名を入力し、MFA デバイスタイプを選択
5. 認証アプリ（Google Authenticator、1Password 等）で QR コードをスキャン
6. 連続する 2 つの認証コードを入力して登録完了

**推奨事項**:

- AWS 公式は **パスキーまたはセキュリティキー（FIDO2）** をフィッシング耐性のある MFA として最も推奨している
- **最大 8 台** の MFA デバイスを登録可能。冗長性のため複数デバイス登録を推奨
- MFA 未設定の場合、初回サインインから **35 日以内** に登録が必須となる（2024 年以降のポリシー）
- ルートユーザーのアクセスキーは **絶対に作成しない**（AWS 公式ベストプラクティス）

> **公式リファレンス**: [Root user best practices](https://docs.aws.amazon.com/IAM/latest/UserGuide/root-user-best-practices.html)

---

### 2. IAM パスワードポリシーの設定

**目的**: IAM ユーザーのパスワード強度を組織全体で統一する。

**手順**:

1. IAM コンソール → **アカウント設定** を選択
2. **パスワードポリシー** の **編集** をクリック
3. 以下を設定して保存

**推奨設定**:

| 項目 | 推奨値 |
|---|---|
| 最小文字数 | 8 文字以上（AWS 上限は 128 文字） |
| 大文字を含む | 有効 |
| 小文字を含む | 有効 |
| 数字を含む | 有効 |
| 記号を含む | 有効 |
| ユーザーによるパスワード変更を許可 | 有効 |

> **注意**: AWS ルートユーザーのパスワードは IAM パスワードポリシーの対象外。ルートには別途強力なパスワードを設定すること。

### 3. 管理者用 IAM ユーザーの作成（個人学習用の場合）

**目的**: ルートユーザーの日常利用を避け、管理者権限を持つ IAM ユーザーで運用する。

> **AWS 公式推奨**: 組織利用では **IAM Identity Center（旧 AWS SSO）** による一時認証情報の利用を強く推奨している。個人学習用アカウントでは IAM ユーザーでも可。

**手順**:

1. IAM コンソール → **ユーザーグループ** → **グループを作成**
2. グループ名を入力（例: `Administrators`）
3. **AdministratorAccess** マネージドポリシーをアタッチ
4. IAM コンソール → **ユーザー** → **ユーザーを作成**
5. ユーザー名を入力、**AWS マネジメントコンソールへのアクセスを提供** にチェック
6. 作成したグループにユーザーを追加
7. 初期パスワードを CSV でダウンロード
8. **作成した IAM ユーザーにも MFA を設定する**（手順はルートと同様）

**運用ルール**:

- 以降はこの IAM ユーザーで日常作業を行う
- ルートユーザーは[ルートユーザーでしかできないタスク](https://docs.aws.amazon.com/IAM/latest/UserGuide/root-user-tasks.html)のみに使用
- 最小権限の原則に基づき、学習が進んだら用途別の IAM ロール/ポリシーに移行する

---

### 4. IAM ユーザーによる請求情報へのアクセス有効化

**目的**: ルートユーザーを使わずに IAM ユーザーで請求情報を確認できるようにする。

**手順**:

1. **ルートユーザー** でサインイン（この設定はルートのみ変更可能）
2. 右上のアカウント名 → **アカウント** を選択
3. **IAM ユーザーおよびロールによる請求情報へのアクセス** セクションまでスクロール
4. **編集** → **IAM アクセスをアクティブ化** → **更新**

---

### 5. Cost Explorer の有効化

**目的**: コストと使用量の可視化・分析を行う。

**手順**:

1. Billing and Cost Management コンソールを開く
2. ナビゲーションペインから **Cost Explorer** を選択
3. 初回アクセス時に自動で有効化される（データ表示まで最大 24 時間）

> **注意**: AWS Budgets を初めて作成する際にも Cost Explorer が自動で有効化される。

## 優先度 B：1 週間以内に対応

### 6. AWS Budgets の設定

**目的**: 意図しない高額課金を早期に検知・通知する。

**手順**:

1. Billing and Cost Management コンソール → **予算（Budgets）** を選択
2. **予算を作成** をクリック
3. **テンプレートを使用（簡易）** を選択
4. **月次コスト予算** テンプレートを選択
5. 予算名・予算額・通知先メールアドレスを入力
6. **予算を作成** をクリック

**本プロジェクトの設定**:

| 項目 | 値 |
|---|---|
| 予算名 | `soa-c03-monthly-budget` |
| 月額予算 | ¥1,500（[aws-rules.md](aws-rules.md) 準拠） |
| 通知閾値 | 実績 85%、予測 100%（テンプレートのデフォルト） |

> **補足**: テンプレート利用時は、実績が予算の 85% に達した時点と、予測が 100% に達した時点で通知メールが送信される。

---

### 7. CloudTrail 証跡の作成

**目的**: API コールの履歴を S3 に長期保存し、「いつ・誰が・何をしたか」を追跡可能にする。

> **デフォルト動作**: CloudTrail はアカウント作成時に自動で有効化され、直近 90 日間の管理イベントを **イベント履歴** で確認できる。ただし S3 への長期保存には証跡の作成が必要。

**手順**:

1. CloudTrail コンソール → **証跡** → **証跡の作成** をクリック
2. 証跡名を入力（例: `management-events-trail`）
3. **新しい S3 バケットを作成** を選択するか、既存バケットを指定
4. ログファイルの SSE-KMS 暗号化（任意、学習用途では不要）
5. **マルチリージョン証跡** は「はい」のまま（AWS 推奨、コンソール作成時のデフォルト）
6. ログイベント → **管理イベント** が記録対象（デフォルト）
7. **証跡の作成** をクリック

**コスト注意**:

- 管理イベントの証跡 1 つ目の S3 配信は **無料**（追加の証跡は課金対象）
- S3 ストレージ料金は別途発生するが、学習用途では微量

> **公式リファレンス**: [Working with CloudTrail trails](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-getting-started.html)

---

### 8. AWS Config の有効化

**目的**: リソースの設定変更履歴を記録し、構成管理と監査を可能にする。

**手順**:

1. AWS Config コンソールを開く
2. **1-click setup**（ベストプラクティスに基づく簡易セットアップ）または **今すぐ始める** を選択
3. 記録対象のリソースタイプを選択（デフォルト: 全リソース）
4. ログ保存先の S3 バケットを指定（新規作成 or CloudTrail と共用可）
5. AWS Config のサービスリンクロールが自動作成される
6. **確認** をクリック

**コスト注意**:

- 記録される設定項目 (Configuration Item) ごとに課金
- コスト削減のため、不要なリソースタイプ（グローバルリソース等）の記録を除外することも検討
- Config ルール（コンプライアンスチェック）は学習段階では不要、レコーダーのみで十分

## 優先度 C：2 週間以内に対応

### 9. Amazon GuardDuty の有効化

**目的**: AWS 環境に対する脅威（不正アクセス、マルウェア等）を自動検知する。

**手順**:

1. GuardDuty コンソールを開く
2. **今すぐ始める** をクリック
3. **GuardDuty を有効にする** をクリック

**推奨事項**:

- GuardDuty は **リージョン単位** のサービス。AWS 公式は **全サポートリージョン** での有効化を推奨
- 初回有効化時に **30 日間の無料トライアル** が適用される
- 本プロジェクトでは最低限 `ap-northeast-1` で有効化する

---

### 10. GuardDuty の通知設定

**目的**: 検出結果をメールで即時通知する。

**手順**:

1. Amazon SNS コンソール → **トピック** → **トピックの作成**
   - タイプ: **Standard**
   - 名前: 例 `guardduty-alerts`
2. **サブスクリプションの作成** → プロトコル: **Email** → 通知先メールアドレスを入力
3. 確認メールの **Confirm subscription** リンクをクリック
4. Amazon EventBridge コンソール → **ルール** → **ルールを作成**
   - イベントソース: **AWS サービス**
   - AWS サービス: **GuardDuty**
   - イベントタイプ: **GuardDuty Finding**
5. ターゲット: 上記で作成した **SNS トピック** を指定
6. （任意）入力トランスフォーマーで通知メールのフォーマットをカスタマイズ
